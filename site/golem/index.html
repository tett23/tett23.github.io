Typesetting,
as software.

Golem は、コマンドラインと CI で動く組版システムです。本をテキストのファイルで書くと、PDF、EPUB、HTML、テキストを組みます。同じ入力からは、どのコンピューターでも同じバイト列の PDF が出ます。

golem new mybook --language ja

組版を、どうソフトウェアにするか

    
本を作る現場では、原稿は Word に、紙面は InDesign に、赤字は PDF に分かれています。三つの写しのあいだで変更を移すのも、赤字が反映されたかをゲラで確かめるのも、人の手と目です。どれだけ注意深く働いても、この形のままでは見落としを防げません。

    
ソフトウェアの開発は、同じ問題を人の注意ではなく仕組みで解いてきました。正本を一つにして変更を残らず記録し、変更のたびに自動で組み立てて検査し、前と違う結果だけを人が確かめる。Golem はこのやり方を組版に持ち込みます。支えるのは次の四つの原則で、どれも前の原則があって初めて働きます。

    
    
      
  1. 
        
    01土台
    
        
    
          
    決定性同じ入力から、一バイトも違わない出力
    
          
    組み上がりを左右する原稿、設定、フォントを、すべてプロジェクトのフォルダに閉じ込めます。Golem はコンピューターに入っているフォントを探しません。同じバージョンの Golem は、どのコンピューターでも中身が一バイトも違わない PDF を作ります。だから出力が変わったら、原因は必ず入力の側にあります。
    
        
    
        
    
          
    Tools
    
          
    • golem buildプロジェクトの中のファイルだけから組む
    
          
    Golem の CI は、x86-64 と aarch64 で同じ原稿を組み、出力のバイト列が一致することを変更のたびに確かめています。保証は PDF、HTML、テキストで、EPUB はまだです。
    
        
    
      
    2. 
      
  2. 
        
    0201 があるから
    
        
    
          
    バージョン管理正本は一つ、変更はすべて履歴に
    
          
    原稿は .gm、体裁の規則は style.toml のテキストです。Git に入れれば、どの行をいつ誰が変えたかが残り、取り込む前に差分で相談できます。PDF はいつでも同じものを組み直せるので、記録するのは原稿と設定だけで足ります。担当者の頭の中にあった組版の規則も、読み返せる履歴になります。
    
        
    
        
    
          
    Tools
    
          
    • git原稿、style.toml、フォントの履歴
    • golem fmt原稿の書き方の揺れをそろえる
    
        
    
      
    3. 
      
  3. 
        
    0302 があるから
    
        
    
          
    CI変更が届くたびに、組んで検査する
    
          
    原稿の置き場所に変更が届くたびに、自動で本を組み、入稿の前の検査（プリフライト）を走らせます。組めなくなった変更や、印刷所の条件に合わなくなった変更は、その回のうちに見つかります。ライセンスの認証がなく、Linux 版は静的にリンクした一つの実行ファイルなので、CI のコンピューターにそのまま置けます。
    
        
    
        
    
          
    Tools
    
          
    • golem check出力を書かずに検査する
    • golem lintlint の規則で原稿を検査する
    • golem preflight入稿の前の検査
    • golem build --profile prod入稿する PDF を作る
    
        
    
      
    4. 
      
  4. 
        
    0401 と 03 があるから
    
        
    
          
    見た目の回帰テスト変わったページだけを、人が見る
    
          
    前に組んだ PDF と新しく組んだ PDF を、ページごとに画像にして比べます。決定性があるので、原稿を変えていないページは画像も同じです。違いが出るのは変更が及んだページだけで、数百ページの本でも、人が確かめるのはそのページだけで済みます。
    
        
    
        
    
          
    Tools
    
          
    • shemPDF のページを PNG に描く
    
          
    Golem 自身の見た目の回帰テストも shem で行っています。ページの画像を比べる機能は Golem には入っておらず、外部のツールで行います。
    
        
    
      
    5.

プラグインと関数で拡張する

    

      

        
プラグイン.wasm

        
組み込みのコマンドで足りないときは、プラグインを足します。プラグインは WebAssembly のファイルで、Golem はプラグインにファイル、ネットワーク、時計、乱数を渡しません。だから、プラグインを使っても同じバイト列に組めます。

        
    
          
  • コマンド段落の中で [furigana: ...] のように呼ぶ
    • 
          
  • ブロックコマンド@tsv-table sales のように呼び、表やブロックを返す
    • 
          
  • フィルタ原稿のファイル一つ分を受け取り、書きかえて返す
    • 
          
  • 一覧本文の各所から集めて、用語集や人名索引を作る
    • 
        


# manifest.toml
[plugins.furigana]
url = "https://example.com/furigana/v1.0.0/furigana.wasm"

$ golem plugin lock   # ハッシュを plugins.lock に書く

      

      

        
関数.emet

        
その本だけの小さな計算や書式は、関数を書く言語 Emet で関数にして、原稿から呼びます。関数が読めるファイルは、マニフェストの [functions.requires] で許したものだけです。


-- fn/numbers.emet
pub inline yen :: Nat -> Inlines
yen n = Inline.text (commas n ++ "円")

-- numbers.gm
@import fn/numbers.emet as n
総額は[n.yen 1234567]です。
→ 総額は1,234,567円です。

        
Emet は Golem の 1.x のあいだ実験的な機能で、二つ目の数が上がったバージョンで書き方が変わることがあります。

インストール

    
リリースから、プラットフォームに合うアーカイブと SHA256SUMS を取得し、照合してから展開します。Linux（x86-64、aarch64）と macOS（Apple Silicon）の配布物があり、Windows では WSL2 の上で Linux の配布物を使います。


TAG=v0.1.0-rc4
curl -LO "https://github.com/tett23/golem/releases/download/$TAG/golem-$TAG-aarch64-macos.tar.gz"
curl -LO "https://github.com/tett23/golem/releases/download/$TAG/SHA256SUMS"
shasum -a 256 --ignore-missing -c SHA256SUMS
tar -xzf "golem-$TAG-aarch64-macos.tar.gz"
install -m 755 "golem-$TAG-aarch64-macos/golem" "$HOME/.local/bin/golem"
golem new mybook --language ja

    
Linux では、アーカイブの名前を x86_64-linux か aarch64-linux にし、sha256sum --ignore-missing -c SHA256SUMS で照合します。macOS の実行ファイルは公証を受けていないので、ブラウザで取得したときは xattr -d com.apple.quarantine golem で属性を外します。
