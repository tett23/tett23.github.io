How Golem makes typesetting software

    
Where books are made, the manuscript is in Word, the pages are in InDesign and the corrections are in a PDF. Moving each change between the three copies, and checking on the proofs that each correction was made, is left to human hands and eyes. However careful people are, this arrangement cannot stop things from being missed.

    
Software development has solved the same problem with mechanisms rather than attention: one master copy with every change recorded, an automatic build and check for every change, and people looking only at results that differ from before. Golem brings this way of working to typesetting. Four principles hold it up, and each works only because of the one before.

    
    
      
  1. 
        
    01the ground
    
        
    
          
    DeterminismFrom the same input, output that does not differ by a byte
    
          
    The manuscript, the settings and the fonts that decide the result are all kept in the folder of the project. Golem does not look for the fonts installed on the computer. The same version of Golem makes a PDF that does not differ by a single byte on any computer. So when the output changes, the cause is always in the input.
    
        
    
        
    
          
    Tools
    
          
    • golem buildtypesets from the files in the project only
    
          
    Golem's CI typesets the same manuscripts on x86-64 and aarch64 and checks, for every change, that the bytes of the output match. This is guaranteed for PDF, HTML and plain text; not yet for EPUB.
    
        
    
      
    2. 
      
  2. 
        
    02because of 01
    
        
    
          
    Version controlOne master copy; every change in the history
    
          
    The manuscript is .gm text, and the rules of the design are style.toml text. Put them in Git, and it records which line was changed, when and by whom, and changes can be discussed as diffs before they go in. Since the same PDF can be typeset again at any time, recording the manuscript and the settings is enough. The rules of typesetting that lived only in someone's head become a history that anyone can read.
    
        
    
        
    
          
    Tools
    
          
    • gitthe history of the manuscript, style.toml and the fonts
    • golem fmtmakes the writing of the manuscript uniform
    
        
    
      
    3. 
      
  3. 
        
    03because of 02
    
        
    
          
    CITypeset and check every change as it arrives
    
          
    Every time a change arrives where the manuscript is kept, the book is typeset automatically and the checks before printing (preflight) are run. A change that no longer builds, or that no longer meets the printer's conditions, is found in that same run. There is no license activation, and the Linux build is a single statically linked executable, so it goes onto a CI machine as it is.
    
        
    
        
    
          
    Tools
    
          
    • golem checkchecks without writing the output
    • golem lintapplies the lint rules to the manuscript
    • golem preflightthe checks before printing
    • golem build --profile prodthe PDF for the printer
    
        
    
      
    4. 
      
  4. 
        
    04because of 01 and 03
    
        
    
          
    Visual regression testsPeople look only at the pages that changed
    
          
    The PDF typeset before and the PDF typeset now are turned into images page by page and compared. Because of determinism, a page whose manuscript did not change gives the same image. Only the pages a change reached differ, so even in a book of hundreds of pages, people check only those pages.
    
        
    
        
    
          
    Tools
    
          
    • shemdraws the pages of a PDF as PNG
    
          
    Golem's own visual regression tests use shem. Comparing the images of pages is not part of Golem; it is done by an external tool.
    
        
    
      
    5. 
    

    

      
    
        
  1. personFix the manuscript.gm and style.toml
    2. 
        
  2. 01 · 02Record itgit commit
    3. 
        
  3. 03Typeset and checkcheck · lint · preflight · build
    4. 
        
  4. 04Compare with the last versionpages as images with shem
    5. 
        
  5. personCheck the changed pagesback to the start to fix
    6. 
      

      
In one round, human hands are needed only at the two black steps. Moving changes between copies and comparing every page of the proofs are not in the loop. Take away any one of the four, and the loop does not close.

Extend it with plugins and functions

    

      

        
Plugins.wasm

        
When the built-in commands are not enough, add a plugin. A plugin is a WebAssembly file, and Golem gives it no files, network, clock or randomness. So a book with plugins still typesets to the same bytes.

        
    
          
  • Commandscalled in a paragraph, like [furigana: ...]
    • 
          
  • Block commandscalled like @tsv-table sales, and give tables and blocks
    • 
          
  • Filterstake one source file and give it back rewritten
    • 
          
  • Listscollect from all over the text into a glossary or an index of names
    • 
        


# manifest.toml
[plugins.furigana]
url = "https://example.com/furigana/v1.0.0/furigana.wasm"

$ golem plugin lock   # writes the hash to plugins.lock

      

      

        
Functions.emet

        
Small calculations and formats for one book are written as functions in Emet, Golem's language for functions, and called from the manuscript. A function reads only the files that [functions.requires] of the manifest allows.


-- fn/numbers.emet
pub inline yen :: Nat -> Inlines
yen n = Inline.text (commas n ++ "円")

-- numbers.gm
@import fn/numbers.emet as n
総額は[n.yen 1234567]です。
→ 総額は1,234,567円です。

        
Emet is experimental during Golem 1.x: how it is written can change in a version whose second number goes up.

"—" marks what the preface of Golem's manual does not compare. Golem cannot typeset mathematics yet. Nor can it, for now, lay out pages directly on screen, place frames anywhere on a page, or print spot colours.

Install

    
Download the archive for your platform and SHA256SUMS from the release, check them, then extract. There are builds for Linux (x86-64 and aarch64) and macOS (Apple silicon); on Windows, use the Linux build under WSL2.


TAG=v0.1.0-rc4
curl -LO "https://github.com/tett23/golem/releases/download/$TAG/golem-$TAG-x86_64-linux.tar.gz"
curl -LO "https://github.com/tett23/golem/releases/download/$TAG/SHA256SUMS"
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf "golem-$TAG-x86_64-linux.tar.gz"
install -m 755 "golem-$TAG-x86_64-linux/golem" "$HOME/.local/bin/golem"
golem new mybook --language en

    
On macOS, use the aarch64-macos archive and shasum -a 256 --ignore-missing -c SHA256SUMS. The macOS executable is not notarized; if a browser downloaded it, remove the attribute with xattr -d com.apple.quarantine golem.
