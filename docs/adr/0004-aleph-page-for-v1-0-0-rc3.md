# ADR 0004: Aleph のページを v1.0.0-rc3 に合わせる

ステータス: 採択→Aleph のページからリンクする版とスクリーンショットの版、リンクの版のテストは [ADR 0006](0006-aleph-page-for-v1-0-0-rc4.md)

## 文脈

[ADR 0003](0003-golem-page-with-golem-wasm-v0-1-0-rc4.md) で、Aleph のページからリンクする版を v1.0.0-rc2 にし、スクリーンショットも v1.0.0-rc2 の `Aleph.app` で撮った。
2026-11-09 に Aleph v1.0.0-rc3（プレリリース）が出て、作業者からページを更新するよう指示があった。

v1.0.0-rc3 のリリースノートと、v1.0.0-rc2 とのタグの差分を読んでわかったことは次のとおり。

- 配布物は `Aleph-v1.0.0-rc3-aarch64-macos.zip` と `SHA256SUMS` の 2 つで、形は v1.0.0-rc2 と同じである。
- 同梱する golem と shem は v0.1.0-rc4 と v0.1.0-rc7 のままで、v1.0.0-rc2 と同じである。
- 公証を受けていないこと、`xattr -dr com.apple.quarantine /Applications/Aleph.app` の手順は v1.0.0-rc2 と同じである。
- `public/icon.svg` は v1.0.0-rc2 から変わっていない。
- 足された機能は次の 2 つである。
  - 問題のパネル：エディタの下に、開いているシートとプロジェクトの診断（check、lint、preflight、build）を集める。ステータスバーの数か ⇧⌘M で開く（Aleph の ADR 0055）。
  - Aleph からのビルド：ツールバーの金槌で、ターゲット、プロファイル、トンボを選んでビルドする。⇧⌘B で前回の選び方でビルドし、結果をステータスバーと問題のパネルに出す（Aleph の ADR 0058）。
- 変わった点は次のとおり。
  - 縦書きで、↓↑ が行の中を、←→ が行のあいだを動く（Aleph の ADR 0059）。
  - ページのプレビューは、入力が 5 秒止まってから組み直す（Aleph の ADR 0056）。
  - 縦書きのシートで、全角の英数字を報告しない（Aleph の ADR 0057）。
- ツールバーに金槌が足されたので、画面の見た目が v1.0.0-rc2 と違う。

[ADR 0002](0002-aleph-page.md) は「版を上げて見た目が変わったら、同じ手順で撮り直す」と決めている。

## 実装すること

[ADR 0002](0002-aleph-page.md) と [ADR 0003](0003-golem-page-with-golem-wasm-v0-1-0-rc4.md) のうち、次の点を変える。ほかの点はそれらの ADR のとおりにする。

### リンクする版

- Aleph のページからリンクする版を v1.0.0-rc3 にする。ダウンロードのボタン、インストールの節の zip と `SHA256SUMS`、リリースノートへのリンクを、すべて v1.0.0-rc3 のタグにする。
- 画面の節の「v1.0.0-rc2 のアプリで撮った画面です」と、Golem との関係の節の「v1.0.0-rc2 は golem v0.1.0-rc4 と shem v0.1.0-rc7 を同梱しています」の版を v1.0.0-rc3 にする。同梱する版はそのままにする。

### スクリーンショット

- 4 枚とも、v1.0.0-rc3 のリリースの zip の `Aleph.app` で、[ADR 0002](0002-aleph-page.md) と `site/aleph/screenshots/README.md` の手順のとおりに撮り直す。見本のプロジェクトも同じものを使う。
- `site/aleph/screenshots/README.md` の版を v1.0.0-rc3 にし、撮った日と、撮ったディスプレイを書きなおす。
- `alt` とキャプションは、映っているものが変わらなければ、そのままにする。

### 機能の一覧

- 機能の一覧に「ビルド」の項目を足し、13 項目にする。ツールバーの金槌でターゲット、プロファイル、トンボを選んでビルドし、⇧⌘B で前回の選び方でビルドできることを書く。「ページのプレビュー」の次に置く。
- 「診断と補完」の項目に、診断を問題のパネルに集めることを書き足す。

### アイコン

- `site/aleph/icon.svg` は変えない。どの版のタグから写したかの記述は v1.0.0-rc2 のままにする（v1.0.0-rc3 でも同じファイルである）。

## 実装しないこと

- 縦書きの矢印キーの動き、プレビューを組み直すまでの待ち、縦書きの全角の英数字の検査を、ページに書くこと。どれも細かな振る舞いで、機能の一覧の粒度に合わない。
- 問題のパネルやビルドの画面を、カルーセルの 5 枚めとして足すこと。カルーセルの 4 枚は [ADR 0002](0002-aleph-page.md) で決めた作業者の指示のとおりにする。
- Retina の画面で撮ること。手元に Retina の画面がなければ、v1.0.0-rc2 のときと同じく等倍で撮り、そのことを README に書く。

## テスト設計

先に書いて失敗させてから実装する。

- `site/aleph/page_test.ts`
  - 今のテスト「すべてのリリースへのリンクが一つのタグで、スクリーンショットの README の版と同じ」は、そのまま使う。
  - ページのリリースへのリンクのタグが v1.0.0-rc3 である。
  - 機能の一覧が 13 項目で、「ビルド」の項目が「ページのプレビュー」の次にある。
  - ページの本文に `v1.0.0-rc2` が残っていない。
- 自動で確かめないこと
  - スクリーンショット：撮った後に 4 枚を開き、v1.0.0-rc3 のツールバー（金槌）が映っていること、ページのプレビューが 300 dpi の設定で描かれていることを目で確かめる。
  - ページ：ローカルのサーバーで開き、カルーセルの 4 枚が出ることを確かめる。

## トレードオフ

- 版を上げるたびに 4 枚を撮り直すのは手間がかかる。古い版の画面を新しい版のリンクと並べると、ページと README の版がそろわず、[ADR 0002](0002-aleph-page.md) の決まりに反する。
- 機能の一覧が 13 項目になり、格子の最後の行が埋まらない。項目を減らしてそろえるより、Aleph にある機能を載せるほうを取る。
